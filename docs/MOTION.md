# 動作設計（轉場與獲勝動畫）

規格第 6 節只明確要求倒數動畫。這份文件是額外的動作規劃，目的是讓計分器
「有比賽感」而不只是能記分。

## 原則

1. **動畫要傳達資訊，不是裝飾。** 每個動畫都要回答一個問題：我往哪走了？剛才加分給誰？誰贏了？
2. **絕不擋住操作。** 動畫進行中畫面仍可觸控；唯一例外是比賽完成頁的按鈕，
   刻意延後 1.4 秒出現，避免慶祝動畫還在跑就被誤觸。
3. **同一頁重畫時不做轉場。** 撤銷後比分更新是「原地改變」，任何位移都會被誤讀成換頁。
4. **時間短。** 轉場 220ms、強調 320–480ms。超過半秒的動畫在連續計分時會讓人不耐煩。

---

## 1. 轉場：方向要對應心智模型

`ui_theme.h` 的 `Nav` 列舉把方向變成明確的參數，而不是每個畫面各自決定：

| Nav | LVGL 效果 | 時間 | 用在哪 |
| --- | --- | --- | --- |
| `Forward` | `MOVE_LEFT` | 220ms | 往流程深處：首頁→賽制→準備、局結果→下一局 |
| `Back` | `MOVE_RIGHT` | 220ms | 退回上一層：任何頁→首頁 |
| `Replace` | `NONE` | 0 | 同一頁重畫：撤銷、重設後更新比分 |
| `Rise` | `OVER_TOP` | 320ms | 儀式性進場：比賽完成 |
| `Fade` | `FADE_IN` | 220ms | 狀態切換：倒數→計分 |

方向走錯比沒有動畫更糟 —— 按「返回」卻看到畫面向左推，會讓人以為又進了一層。

`Rise` 只用在比賽完成一處。由下往上覆蓋的動作本身就有「揭曉」的意味，
用多了就不特別了。

---

## 2. 倒數（頁面四）

| 元素 | 動作 |
| --- | --- |
| 圓形進度環 | 300px 直徑，3 秒走完一圈。圓形螢幕本來就適合放圓環，這是形狀優勢 |
| `3` `2` `1` | 每個數字從 1.6 倍收縮到原尺寸（`animPop(410 → 256)`），像砸在畫面上 |
| `GO!` | 反過來由 0.35 倍放大到原尺寸，配合過衝路徑做出爆發感 |
| `GO!` 光環 | 金色光環由中心擴散 |
| 進度環顏色 | 倒數時是 P2 紅，`GO!` 時轉金色 |

第一個 `3` 在畫面建立時就要觸發 `animPop`，否則第一拍會少一次彈跳，
看起來像是動畫壞掉。

---

## 3. 計分畫面（頁面五）

**只讓分數有變動的那一邊彈跳。** 兩邊都動等於沒有指向性，使用者反而看不出
剛才加到誰身上。

實作靠 `screen_score.cpp` 的 `s_shownP1` / `s_shownP2` 快照 —— 畫面每次都重建，
狀態只能留在 file-static。全新一場（`undoAvailable() == 0`）不做強調，
否則第一次進場兩邊都會亂彈。

撤銷造成的分數**下降**同樣會彈跳。那也是一次狀態改變，值得回饋。

---

## 4. 局結果（頁面六）

| 元素 | 動作 | 用意 |
| --- | --- | --- |
| 勝利方式（如「P1 爆裂勝」） | 淡入 260ms | 先讓人讀到發生什麼事 |
| 得分（`+2`） | 彈出，延遲 180ms | 分數越高彈得越誇張：`+1` 幾乎不動（180→256），`+2` 中等（120→256），`+3` 明顯（60→256） |
| Xtreme Finish | 追加金色光環循環 | 本作最高分的收尾方式，值得專屬效果 |

「得分越高動得越誇張」是這裡的核心 —— 動畫幅度本身就在傳達分數大小，
不用讀數字也感覺得到剛才那一擊有多重。

---

## 5. 比賽完成（頁面七）

依序登場，讓視線由上而下跟著跑：

| 時間 | 元素 | 動作 |
| --- | --- | --- |
| 0ms | 勝者色光環 ×2 | 由中心擴散並淡出，1.8 秒循環，第二圈延遲 900ms 錯開半個週期 |
| 0ms | 「比賽結束」 | 淡入 300ms |
| 150ms | 「勝者」／「平手」 | 由 0.23 倍彈到原尺寸，480ms |
| 380ms | 勝者名稱 | 淡入 320ms |
| 550ms | 比分 | 兩邊各自從 0 跑到最終分數，700ms |
| 1100ms | 「共 N 局」 | 淡入 |
| 1250ms | 「已儲存」 | 淡入 |
| 1400ms | 按鈕 | 淡入 |

**比分為什麼拆成三個 label**：原本是單一 `"%d : %d"` 字串，只能整串一次換掉，
沒有揭曉感。拆成「P1 分數 / `:` / P2 分數」後，兩邊才能各自 count-up。

兩圈光環錯開半個週期，看起來是連續脈動而不是一閃一閃。兩者都在背景層
（`lv_obj_move_background`）且清掉 `CLICKABLE`，不會擋到按鈕觸控。

## 6. 技術細節

### transform_zoom 的 pivot 陷阱

LVGL 的 `transform_zoom` 以 pivot 為中心，而 pivot **預設在左上角**。
不校正的話物件會一邊放大一邊往右下漂移。`animPop()` 因此必須先呼叫
`lv_obj_update_layout()` 讓 LVGL 算出尺寸，才有正確的中心點可設。

### 記憶體

縮放會讓物件先被畫到一塊暫存圖層再變形，需要：

- `LV_DRAW_COMPLEX = 1` ✅
- `LV_LAYER_SIMPLE_BUF_SIZE = 24KB` ✅

最大的變形對象是 30px 的勝者標籤（約 200×36 = 14KB）與 48px 的倒數數字
（約 60×60 = 7KB），都在預算內。

### 動畫的生命週期

LVGL 會在物件被刪除時自動移除其動畫，因此畫面切換（`auto_del = true`）
不需要手動清理。**例外是 `lv_timer`** —— 倒數畫面的計時器必須在
`LV_EVENT_DELETE` 中明確 `lv_timer_del`，否則下一次 tick 會操作已釋放的 label。

## 尚未實作（後續規劃）

以下是有價值但這一版沒做的，依優先序：

1. **勝利類型選單的進場動畫** —— 目前疊層是瞬間出現。應該由對應玩家那一側滑入，
   強化「這是 P1 的選單」。
2. **長按進度指示** —— 規格第 6 節的「長按玩家區域直接加 1 分」目前沒有視覺回饋，
   使用者不知道還要按多久。應該加一圈跟著長按進度走的環。
3. **分數逼近賽末點的提示** —— 距離目標分數只差 1 分時，該玩家的分數可以持續微幅脈動。
4. **IMU 連動**（Phase 5）—— 板上有 QMI8658。搖晃裝置觸發倒數、或在得分時
   讓畫面依傾斜方向輕微位移，會很有玩具感。
5. **音效同步**（Phase 5）—— 目前 `feedbackPlay()` 的呼叫點都已埋好且與動畫時間對齊，
   接上音訊後不需要調整動畫時序。
